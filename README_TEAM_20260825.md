# MISHARP HERO ITEM OS v3.0 — 2026-08-25 팀 협의 반영

## 핵심 방향
이번 개편은 "히로 점수를 보는 프로그램"에서 "신상품을 자동으로 발견하고 48시간 뒤 판정과 후속업무를 공유하는 운영 OS"로 역할을 바꿉니다.

## 메뉴
1. 상품 탐색
2. 상품 판정 및 후속업무 관리
3. 미샵 DNA
4. 상품DB
5. 데이터·설정

상단의 `이용방법`은 기능 메뉴가 아니라 직원용 도움말 페이지입니다.

## 상품 탐색
- Cafe24 API: 최근 등록 + 판매중 + 진열중 상품이 공식 자동탐색 기준
- 홈페이지 크롤링: 실제 노출 여부 교차확인용 보조 신호
- 자동탐색 상품은 48시간 관찰을 자동 시작
- 신규 등록 직후 첫 Cafe24 Analytics 데이터 수집
- 이후 30분 주기 자동갱신

## 48시간 후 자동 이동
48시간이 지나면 상품은 `상품 탐색`에서 사라지고
`상품 판정 및 후속업무 관리`에 자동으로 나타납니다.

## 상품 판정표
- 상품명
- 반품률
- 상품등급
- 자동진단
- WHY
- 판정
- MD팀업무
- 제작팀업무
- 기타 메모

후속업무는 DB에 저장되어 모든 직원이 같은 내용을 봅니다.

## WHY 원칙
WHY는 단순한 HERO/재검토 문구가 아닙니다.
- 상품조회수
- 구매전환율(CVR)
- 조회당 매출(RPV)
- 판매수량
- 매출
- 반품률(48시간 이후)

을 근거로 진단과 추천행동을 설명합니다.

공식 성과 데이터는 Cafe24 Analytics 하나만 사용하며 SERA/Sellmate를 판정값에 섞지 않습니다.

## 과거 데이터 원칙
- 전체 상품DB는 회사 자산으로 계속 보존
- 비교/예측은 최근 3년 데이터 우선
- 최근 3년 48H 비교집단이 부족하면 현재 누적 완료상품으로 fallback
- 과거 36개월 Analytics 월별 히스토리는 별도 backfill workflow로 준비

## 팀 공용 접근
상품DB와 데이터·설정은 별도 비밀번호 없이 팀에서 함께 사용합니다.

## 미샵 DNA
최근 3년 실제 판매성과에서 시기별 상위상품의 카테고리·가격대·반응지표·상품명 핵심어를 추출해 다음 신상품 기획의 질문과 우선순위를 제안합니다.

## 자동화
`.github/workflows/sync_30min.yml`
- 매시 17분/47분
- 신상품 자동탐색
- 48시간 판매반응 갱신
- 48시간 완료상품 반품률 갱신

`.github/workflows/sync_daily.yml`
- 매일 KST 03:13
- 상품DB 전체 재검증
- 최근 Analytics 갱신
- 신상품 자동탐색 재검증

`.github/workflows/history_backfill.yml`
- 관리자 수동 실행
- 최근 36개월 학습데이터 backfill
